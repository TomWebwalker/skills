# Issue tracker

None. Work is tracked in the PR itself.

Skills skip every ticket step: `start-issue` asks for a slug instead of a ticket id,
`qa-local` presents QA steps in chat rather than posting a comment, and
`finalize-feature` puts the QA notes in the PR description.
